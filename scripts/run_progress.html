Как читать страницу и что записывает менеджер 
Страница - читаемая сторона офиса; ее открывает кнопка Journal, тот же адрес - путь /details у напечатанного URL офиса. Разделы: Разговор, Сессии, Метрики, Журнал. Графа цикла и дуги возврата здесь нет: в разделе Журнал одна строка на попытку, а в строке по фишке на каждую фазу - сборка, проверки, ревью, triage, verify, решение, handoff. Фаза без собственных записей так и подписана: нет записей. Работой считается только наблюдаемая запись CLI текущей попытки: запрошенный, но еще не наблюдавшийся запуск показан как "запуск запрошен, активность не наблюдалась".
Сцена и персонажи - Pixel Agents (MIT, Copyright (c) 2026 Pablo De Lucca); спрайты восходят к пакету MetroCity. Движок и ассеты скопированы байт в байт из закрепленной ревизии и собраны заранее. Запуск - python3 scripts/run_progress.py serve --progress-dir DIR: команда поднимает Python-сервер журнала, рядом Node-адаптер офиса и печатает URL офиса. Состояния берутся из тех же журналов, что и остальная страница.
Этапы: работает (желтый), ожидает менеджера (сиреневый пунктир), тишина без подтверждения (серый точечный), CLI завершил успешно без приемки (синий), завершен или принят (зеленый), ошибка (красный), запуск запрошен без наблюдаемой активности или записей об этапе нет (серый). Результаты проверок и ревью попадают сюда из приемочных расписок автоматически и помечены "по расписке"; зарегистрированный разбор показан как факт регистрации, его состав не разбирается.
Тишина не означает завершения: состояние шага подтверждают только записи helper и менеджера. Активность считается по обоим потокам: журналу метаданных и трассировке сообщений.
Успешный выход CLI не является приемкой задачи: приемку записывает только менеджер.
Токены: итог по завершенным вызовам, промежуточные снимки помечены; неизвестное показано как неизвестное, не как ноль; "не менее" означает, что часть вызовов счетчик не сообщила.
Вход Claude = без кеша + создание кеша + чтение кеша (все три оплачиваются отдельно); у Codex кешированный вход входит в общий вход; рассуждения входят в выход.
Контекст: размер последнего запроса к API (вход + кеш последнего сообщения), не текущая занятость и не сумма по всем ходам; емкость окна - по итогу CLI для Claude и по каталогу моделей CLI для Codex; занятость и остаток контекста headless-потоки не сообщают.
Лимиты аккаунта - только из событий CLI с их статусом; бюджет - только заданный явно. Оценка $ - расчет CLI, а не списание с подписки.
Обвязка: выбранные скиллы, агенты и MCP - это то, что менеджер выбрал и лаунчер внедрил в системный промпт; наблюдаемые вызовы - то, что CLI реально вызвал; сверка (audit) и claude doctor - записи после выхода CLI. Внедренный текст не доказывает соблюдение скилла; каталог сессии - доступные компоненты, а не вызванные.
Импорт старых журналов помечен; время наблюдения показывается только когда его сообщают артефакты запуска, иначе оно неизвестно.

Команды менеджера (из корня обвязки, --progress-dir общий для задачи):
  python3 scripts/run_trace.py register --progress-dir DIR --role user --kind user_prompt --file prompt.md
  python3 scripts/run_trace.py register --progress-dir DIR --role manager --kind feedback --file review-1-triage.md
  python3 scripts/run_trace.py register --progress-dir DIR --role manager --kind decision --text "RETRY: ..."
  python3 codex/scripts/run_codex_review.py --workspace WS --prompt review-1.md --output-dir RUN/review-1 --progress-dir DIR
  python3 scripts/run_trace.py import-claude --progress-dir DIR --launcher-dir RUN/build-1 --attempt 1 --step-id build-1
  python3 scripts/run_trace.py budget --progress-dir DIR --tokens N
