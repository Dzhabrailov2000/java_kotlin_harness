Ты работаешь с Architecture Decision Record (ADR) в базе знаний команды EMM (Enterprise Mobility Management), репозиторий `~/IdeaProjects/reactive-uem-architecture`. ## Шаг 0. Решение должно быть уже принято

ADR фиксирует принятое решение, а не предлагает его. Если из запроса неясно, что именно решено, остановись и спроси. Не ставь статус `accepted` решению, которого пользователь не принимал: по умолчанию новая запись это `proposed`.

Стоячее правило пользователя: "Не дописывать в материалы непринятые или спекулятивные тех-детали. Только решенное и необходимое; неутвержденное помечать явно." Формулировка была в `~/work/CLAUDE.md` и при переезде 2026-08-25 в новый репозиторий не перенеслась. Правило действует, но опереться на файл нельзя: если пользователь спросит про источник, скажи это прямо.

- `~/IdeaProjects/reactive-uem-architecture/docs/adr/` - решения по продукту и архитектуре Reactive UEM / LwM2M (Lightweight Machine-to-Machine): язык, фреймворк, персистентность, маршрутизация, провижининг, фазы.
- Каталог ADR по инфраструктуре разработки (inner/outer loop, окружения по ветке, правила общей базы данных) осиротел. Если тема относится сюда, НЕ пиши ни в старое дерево, ни в новое молча: сообщи пользователю, что дом этих записей не определён, и спроси, куда класть.

Если тема не ложится однозначно в один из них, спроси. Не заводи запись "на всякий случай" в оба.

## Шаг 2. Определить номер

В материалах правило выбора номера не задано. Фактически ряды сплошные, без пропусков и без переиспользования. Действуй так: прочитай индекс README целевого каталога, возьми максимальный номер и прибавь единицу. Если в каталоге есть файл с таким номером, а в индексе его нет, остановись и скажи об этом: расхождение чинит человек.

## Шаг 3. Создать файл

Каталог `reactive-uem/adr/`:

- Имя файла: `ADR-NNNN-<slug>.md`, NNNN это четыре цифры с ведущими нулями, slug латиницей в нижнем регистре через дефис. Правило нигде не записано текстом, оно выведено из всех 12 существующих имён.
- Тело: копия `template.md` этого каталога. Секции строго: H1 `# ADR-NNNN: <короткое название>`, затем четыре буллета метаданных без заголовка секции (`- **Статус:**`, `- **Дата:**`, `- **Авторы:**`, `- **Причастные:**`), затем `## Контекст`, `## Решение`, `## Рассмотренные альтернативы`, `## Последствия` с тремя буллетами `- **Плюсы:**`, `- **Минусы / цена:**`, `- **Открытые вопросы:**`.
- Записи ADR-0001..ADR-0010 идут по старому английскому набору заголовков (`## Status`, `## Context`, `## Decision`, `## Alternatives considered`, `## Consequences`, `## Follow-ups`). Для новых записей его НЕ используй: README велит копировать `template.md`. Легаси не трогай.
- Альтернативы в живых записях 0011 и 0012 оформлены как `- **<Название варианта>.** <проза: плюсы, минусы, почему не выбран>`, а не как `- **Вариант A** - ...` из шаблона. Бери форму живых записей.

Каталог `apps-ci/docs/adr/`:

- Имя файла: `NNNN-<slug>.md`, без префикса `ADR-`. При этом H1 внутри файла префикс содержит: `# ADR-NNNN: <название>`.
- Тело: копия `template.md` этого каталога. Метаданные тремя строками без буллетов: `**Date**: YYYY-MM-DD`, `**Status**: ...`, `**Deciders**: ...`. Секции `## Context`, `## Decision`, `## Alternatives Considered` с вложенными `### Alternative N: <название>` и буллетами `- **Pros**:`, `- **Cons**:`, `- **Why not**:`, затем `## Consequences` с `### Positive`, `### Negative`, `### Risks`.
- Шаблон английский, тела записей русские. Единого правила по языку заголовков для новых записей в материалах нет. Если пишешь новую запись в этот каталог, спроси, оставлять ли английские заголовки шаблона.
- Плейсхолдеры шаблона в квадратных скобках обязательно замени. В `0001` они остались незамененными, это дефект, а не образец.

## Шаг 4. Заполнить содержание

- Язык тела русский.
- `## Контекст` (или `## Context`): какую проблему решаем, какие ограничения и силы действуют. Факты, а не выводы.
- `## Решение` (или `## Decision`): что именно решили, в настоящем времени. "Используем X", "Заводим Y".
- Альтернативы: только те, что реально рассматривались, с причиной отклонения. Не выдумывай альтернативы для симметрии.
- Последствия: плюсы, цена, открытые вопросы.
- Одна запись это одно решение. Если в теме два независимых решения, скажи об этом и предложи две записи.

Обязательные правила оформления. Первые три взяты из живого файла `~/IdeaProjects/reactive-uem-architecture/CLAUDE.md`, раздел "Конвенции документов". Последние два были в `~/work/CLAUDE.md` и при переезде потерялись, но остаются стоячими правилами пользователя:

- Пунктуация только ASCII, как при ручном наборе: без длинных тире, стрелок, ёлочек, многоточий, галочек. Дефис с пробелами вместо тире.
- Аббревиатуры расшифровывать в скобках при первом упоминании в документе (TCP, UDP, PSK, DTLS и подобные).
- Кросс-ссылки относительные, чтобы набор оставался самодостаточным.
- Wikilinks не используем (правило потеряно при переезде, действует по указанию пользователя).
- При добавлении ADR дописывать строку в индекс (правило потеряно при переезде, но фактически индекс ведётся, см. шаг 5).

## Шаг 5. Дописать строку в индекс

Правило из CLAUDE.md: "При добавлении сервиса, ADR или контракта дописывать строку в индекс." Индекс это единый источник истины по статусам.

`reactive-uem/adr/README.md`, раздел `## Индекс`, таблица `| № | Решение | Статус |`. Строка:

```
| [NNNN](ADR-NNNN-<slug>.md) | <формулировка решения> | <статус> |
```

Номер в первой колонке без префикса `ADR-`, только четыре цифры, ссылкой на файл. Встречающиеся формы статуса, других не изобретай:

- `Proposed (YYYY-MM-DD)`, при ревизии `Proposed (YYYY-MM-DD, рев. YYYY-MM-DD)`
- `Accepted (YYYY-MM-DD)`
- `Deferred -> Фаза N`

Строки для `superseded` и `rejected` в индексе не встречались ни разу. Если заводишь такую, спроси форму у пользователя, не придумывай.

`apps-ci/docs/adr/README.md`, таблица `| ADR | Title | Status | Date |`. Строка:

```
| [NNNN](NNNN-<slug>.md) | <Title> | <status> | <YYYY-MM-DD> |
```

Статус строчными буквами, дата отдельной колонкой. Title должен совпадать с H1 файла: для `0002` они сейчас расходятся, это дефект, не повторяй.

## Шаг 6. Бэклог кандидатов

Только в `reactive-uem/adr/README.md` есть раздел `## Кандидаты на ADR (бэклог)`. Если новая запись закрывает пункт этого списка, пункт НЕ удаляй, а оформи так:

```
- ~~<исходная формулировка>~~ - решено: <чем закрыто, ссылка на ADR или тикет>.
```

В `apps-ci` раздела бэклога нет. Не заводи его сам.

## Шаг 7. Смена статуса и перекрытие решений

Правило из CLAUDE.md: "ADR не правятся задним числом. Отмененное решение получает статус superseded by ADR-XXXX, новое пишется отдельной записью."

При смене статуса существующей записи:

- Тело решения не переписывай. Меняй только поле статуса и строку индекса.
- Прецедент перевода в accepted (ADR-0012): в конец записи дописывается секция `## Статус реализации (дописано YYYY-MM-DD при переводе в accepted)`, начинающаяся фразой "Тело решения выше не правится задним числом; здесь фиксируется, что из него исполнено", с жирными подзаголовками-абзацами `**Исполнено в <репозиторий> (ветка <ветка>):**`, `**Не исполнено:**`, `**Остаётся открытым:**`. Обязательность этой секции в материалах не задана: спроси, нужна ли она.
- Прецедент ревизии без смены решения (ADR-0007, 0008, 0010): блок `### Обновление YYYY-MM-DD (<повод>)` сразу после секции статуса. В `apps-ci` та же по смыслу секция оформлена иначе: `## Обновление YYYY-MM-DD: <текст>` в конце документа. Единой формы нет, держись формы того каталога, в котором работаешь.

При перекрытии старого решения новым:

- Старую запись пометь `superseded by ADR-XXXX`, тело не трогай.
- Прецедент указателя (ADR-0009): в начало секции статуса перекрытой записи добавлена блок-цитата `> **Указатель (YYYY-MM-DD):** пункт ... **закрыт** решением [ADR-XXXX](ADR-XXXX-<slug>.md)`. Правилом это не объявлено, но прецедент один и он рабочий. Спроси, добавлять ли.

## Шаг 8. Самопроверка перед сдачей

1. Пунктуация в новом файле и в правке индекса только ASCII.
2. Все аббревиатуры расшифрованы при первом упоминании.
3. Номер файла, номер в H1 и номер в индексе совпадают.
4. Формулировка решения в индексе не противоречит H1 файла.
5. Ни одного плейсхолдера шаблона (угловые или квадратные скобки) не осталось.
6. В теле нет решений, которых пользователь не принимал.
7. Дата в метаданных и дата в индексе согласованы. Для ADR-0012 в индекс попала дата принятия, а не поле "Дата"; если у тебя эти даты расходятся, спроси, какую ставить.

В конце покажи пользователю: путь нового файла, добавленную строку индекса и список того, что ты спросил бы, но решил по умолчанию.
