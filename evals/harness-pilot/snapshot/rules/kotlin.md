# Kotlin

- ООП и идиомы Kotlin. Стек, тест-стек, язык логов и комментариев - как уже есть в репозитории, не
  выравнивать.
- Без `!!`. `when` по sealed - без `else`. CancellationException не глотать, suspend не заворачивать в
  `runCatching`. Вложенность scope-функций (`let`, `apply`, `also`, `run`) - не больше двух.
- Классы и типы называй существительными, обычные методы и функции - глаголом или глагольной фразой
  (`findDevice`, для Boolean - `isExpired`). Исключения: фабрики с именем типа, операторы,
  переопределения внешнего API и @Bean-методы Spring.
- Формат - ktlint через Gradle-плагин: `./gradlew ktlintFormat` перед коммитом там, где плагин подключен.
  Отдельный ktlint из brew не ставить: другая версия - другой формат.

## Комментарии
- KDoc - как принято в репозитории (обычно на публичном API). В остальном комментарий только там, где
  логика неочевидна; пояснение на месте - `//` одной строкой.
- Пиши "почему", а не "что": причина, ограничение, инвариант, побочный эффект, потокобезопасность.
- В своих сервисах комментарии и KDoc - по-русски, идентификаторы - по-английски. Неочевидные
  аббревиатуры расшифровывай при первом упоминании в файле.
- Нельзя: закомментированный код, комментарий в противоречии с кодом, пересказ имени.
- TODO и FIXME без ключа задачи не оставляй. Где правила проекта запрещают ссылки на задачи в коде, вместо
  TODO - пункт в отчете, чтобы завести задачу.

## Тесты
- Новый сервис: JUnit 5, MockK, Testcontainers, Kover; Kotest не используем.
- В существующем - как уже принято: ассерты (kotlin.test, AssertJ или JUnit) и Mockito там, где он есть.
  Чужие ассерты не переписывай, Mockito и MockK в одном файле не смешивай.
- Классы: `XxxTest` - модульный, `XxxIntegrationTest` - поднимает Spring-контекст или Testcontainers,
  `XxxGuardTest` - держит инвариант сборки или окружения.
- Методы - имя в обратных кавычках, английское повествовательное предложение:
  `` `returns 503 when service hits a database error` ``. В новом коде без `@DisplayName` и `@Nested`.
- Без комментариев `// Given`, `// When`, `// Then`: блоки разделяет пустая строка. Комментарий в тесте
  объясняет, почему случай важен.
- Порог Kover и исключения - решение репозитория: смотри сборку. Исключают только то, что по природе не
  покрывается модульными тестами: точку входа и конфигурацию бинов.
