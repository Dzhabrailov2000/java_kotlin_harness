# Подготовка к встрече

Вход: $ARGUMENTS

Ты готовишь пользователя к встрече как ведущего или архитектора. Через индекс документации проекта
прочитай по теме: статусы в индексе ADR, затронутые ADR и контракты, нарезки и оценки, прошлые протоколы -
чтобы не открывать закрытое и явно назвать решенное. Утверждения - со ссылками на источники. Индекса нет
или тема не покрыта - спроси, где искать.

Структура - как у последнего документа подготовки в проекте (скажи, какого). Образца нет - предложи эту
рамку:

```
## 1. Цель (держать как рамку)
## 2. Повестка (предложение тайминга)
## 3. Каркас задач (для груминга и оценки)
## 4. Решения, которые нужно принять на встрече (не оставлять открытыми)
## 5. Риски - поднять заранее, чтобы не всплыли сюрпризом
## 6. Что взять на встречу
## 7. Заметки по итогам (заполнить на встрече)
```

Шапка: `# Подготовка к <тип встречи>: <тема>`, роль пользователя на встрече, связанные документы и ADR.
- Повестка - с таймингом по минутам, в сумме равным длительности встречи.
- Каркас задач - с приоритетом (обязательно / может подождать), по эпикам с ролью-владельцем, у каждого
  пункта "Зачем:".
- Блок "как читать" - термины для тех, кто без контекста.
- Решения - развилки с обязательной рекомендацией автора: встреча - не место для открытого перечня.
- Итоги - пустая рамка: "Принятые решения:", "Взятые в спринт задачи / владельцы:", "Открытые вопросы:",
  "Следующий шаг:".

Если у другой стороны уже есть свой план и встреча о том, как их совместить, нужен другой документ: дельта
и решения, а не параллельный план. Позиция - дополнить и зафиксировать, а не конкурировать:

```
## A. Добавить в план команды (наша дельта - этого у них нет)
## B. Закрыть открытые вопросы (решения, не задачи)
## C. Зафиксировать в ADR (где их план меняет или подтверждает наши решения)
## D. Подтянуть из их плана к себе (их сильные стороны - принять)
## Как подать на встрече (одна фраза)
```

Такой документ заканчивается готовой фразой в кавычках, чтобы сказать ее вслух. Из темы неясно, какой
документ нужен, - спроси.

Файл - по правилу проекта; правила нет - предложи каталог рядом с протоколами и спроси, новые каталоги
молча не создавай. Непринятые детали не добавляй; статусы решений не дублируй, а ссылайся на индекс ADR.

В конце - путь к файлу, повестка с таймингом отдельным блоком, развилки с твоей рекомендацией и чего не
нашел в материалах.
