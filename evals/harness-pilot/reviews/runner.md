# Независимое ревью запускателя пилота

Открытых подтвержденных critical/major замечаний после повторной проверки нет. Найденный major дефект коротких имен collaboration исправлен и перепроверен локально. Доступность этих инструментов честно раскрыта в протоколе. Основной замер на момент проверки не начат.

## Закрытый major: проверка части collaboration-вызовов использовала неверное имя

Файл: `evidence.py:69-75`.

Код сохраняет только `item.name` из реального ответа Responses API. Имена инструментов в этом поле не обязаны содержать namespace. В реальном сохраненном ответе `preflight/20261006T154700-codex-A/http/0002-response.bin` вызов пространства `functions` записан как `name=exec`, а не `functions.exec`. В соответствующем HTTP-запросе инструмент делегирования имеет `name=send_message` внутри namespace `collaboration`.

Запрет проверяет `collaboration.send_message`, `collaboration.list_agents`, `collaboration.interrupt_agent`, `collaboration.wait_agent`, но не их короткие имена. Поэтому такие фактические вызовы проходят с `context_valid=true`, хотя правило эксперимента запрещает любой collaboration-вызов. Это дефект измерения соблюдения условия "один агент", даже если уже выполненные предварительные пробы таких вызовов не содержат.

Подтверждение без обращения к модели: во временном каталоге создан минимальный stdout с `turn.completed`, HTTP request с моделью `gpt-6-astra` и SSE-событие `response.output_item.done` с `type=function_call`. Для каждого `name` из `send_message`, `list_agents`, `interrupt_agent`, `wait_agent` текущий `summarize(..., 'codex', 'A')` вернул `context_valid=true`, `forbidden_delegation=[]`.

Исправление выполнено основным исполнителем: `evidence.py:70-77` сохраняет namespace и запрещает также короткие имена. Повторная локальная проверка без модели отклонила send_message, list_agents, interrupt_agent, wait_agent, spawn_agent, followup_task и collaboration.send_message. Контрольный обычный exec остался допустимым. Исходники запускателя проверяющий не изменял.

## Проверенные свойства

- Прочитаны `core.md`, все шесть файлов из задания, `PLAN.md`, конфигурация задач и релевантные сохраненные предварительные HTTP-запросы/ответы.
- Каждая попытка использует отдельный рабочий каталог и новый процесс. Профиль внешней песочницы применяется одинаково к обоим условиям. `danger-full-access` во внутреннем Codex не трактуется как отсутствие внешнего seatbelt.
- Скрытые исходники задач и проверки лежат вне рабочего каталога; текущий профиль закрывает IdeaProjects и прочие `/private/tmp/jkh-*`, кроме собственного рабочего каталога. Эта последняя редакция профиля прочитана повторно в ходе обзора.
- Grader восстанавливает исходную сборку и тесты и переносит только production sources из попытки. Замена существующих тестов или build.gradle в рабочем каталоге не подменяет независимые проверки.
- Runner не перезаписывает существующую попытку и требует явного разбора прерванного каталога. Ошибка процесса и отсутствие завершающего события исключают `valid_attempt`. Успех скрытых тестов хранится отдельно от валидности попытки.
- `http_requests` включает служебные GET; `model_requests` считается по записанным запросам с полем model. В проверенных пробах последние соответствуют `/v1/messages` или `/backend-api/codex/responses`, а запросы списка моделей учитываются только в общем HTTP-счетчике.
- Usage Claude нормализуется как обычный вход плюс создание и чтение кэша; исходный usage сохраняется. Денежная величина названа оценкой по прейскуранту. Usage не суммируется повторно по промежуточным событиям.
- Заголовки авторизации transport не сохраняет. В исследованных запросах путь не содержит credential query parameters. Файлы авторизации не читались, не копировались и не изменялись проверяющим.
- Автоматических лимитов времени модели нет. Это соответствует прямому правилу core.md; отсутствие произвольного timeout не является находкой этого ревью.

## Границы доказательств

Флаги Codex `--disable multi_agent` и `multi_agent_v2` не удалили namespace collaboration из реально отправленного HTTP-контекста. В проверенных Codex A/B пробах он присутствует. Поэтому допустимо утверждать отсутствие наблюдаемых вызовов после исправления проверки, но нельзя утверждать отсутствие доступных инструментов делегирования.

Claude B передает core и Kotlin rule, но Java/Kotlin skills в snapshot имеют `disable-model-invocation: true`. Их имена видны в init, а каталог naming не виден в рассмотренных HTTP-запросах. Это свойство проверяемой конфигурации, а не доказательство автоматического применения навыков. Codex B каталог передает. Межклиентскую симметрию загрузки навыков по этим данным утверждать нельзя.

Профиль с `allow default` не является общей песочницей только для workspace: в частности, доступ к глобальному Gradle-кэшу нужен существующей конфигурации. После обсуждения основной исполнитель добавил запрет записи в HOME с исключениями для runtime-каталогов .claude/.codex/.gradle и отдельные запреты записи в Gradle init.d, init.gradle, init.gradle.kts, gradle.properties и files-2.1. `grade_code` теперь также запускает `run_check(..., isolated=True)` под внешним sandbox. Эти изменения прочитаны по коду; проверка полноценного запуска сборки под итоговым профилем остается у основного исполнителя. Защита всех секретов HOME этим обзором не доказана. Фактического загрязнения общей установки не найдено.

`PROTOCOL.md:42-45` теперь явно раскрывает доступность collaboration и отличает ее от отсутствия фактического делегирования. `PROTOCOL.md:32-40` раскрывает разницу загрузки навыков Claude/Codex. Таким образом, замечание к заявлению о недоступности инструментов закрыто, а ограничение не скрывается за CLI-флагами.
