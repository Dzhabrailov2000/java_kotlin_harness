**Попытка опровергнуть решения**

Для каждого пакета вручную прослежены следующие входы; это анализ кода, а не дополнительный запуск:

- [(a, x, USD, 2.0), (a, x, USD, 2.00)] дает одну продажу с числовой суммой 2.
- [(a, x, USD, 2), (a, x, EUR, 2)] и [(a, x, USD, 2), (a, x, USD, 3)] вызывают IllegalArgumentException.
- [(b, x, USD, 1.125), (a, x, USD, 2.0), (a, x, USD, 2.00), (a, y, USD, -0.125), (a, z, EUR, 5)] дает в порядке сортировки (a, EUR, 1, 5), (a, USD, 2, 1.875), (b, USD, 1, 1.125).
- Пустой список дает пустой результат; все изменяемые коллекции создаются внутри вызова, исходный список и его элементы не изменяются.

В этих примерах суммы представлены десятичными строками для BigDecimal. Контракт не задает scale итогового BigDecimal, поэтому различие представления при равном числовом значении не считается дефектом. Пропущенный тестами дефект с воспроизводимым входом не установлен. По одним счетчикам тестов нельзя установить полноту покрытия; отсутствие находок относится только к этим четырем пакетам и заданному контракту.
