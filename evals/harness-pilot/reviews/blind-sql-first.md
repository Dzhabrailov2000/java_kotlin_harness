Во всех четырех пакетах migrations/V2__balance_check.sql содержит BEGIN в строке 1, ADD CHECK ... NOT VALID в строке 2, VALIDATE CONSTRAINT в строке 3 и единственный COMMIT в строке 4. Поэтому полученная при ADD блокировка AccessExclusiveLock остается на время сканирования VALIDATE. Она несовместима с AccessShareLock обычного SELECT и RowExclusiveLock обычных INSERT/UPDATE. Каждый участник описал именно эту причинную связь; никто не приписал самостоятельному VALIDATE получение AccessExclusiveLock.

Воспроизводимый сценарий каждого замечания соответствует контракту: после получения блокировки строкой 2 и во время длительного сканирования строки 3 обычное обращение к accounts из другой транзакции ожидает завершения миграции.
