# Независимое ревью постобработки пилота

Подтвержденных critical/major дефектов в проверенной постобработке и промежуточном отчете не найдено. Вывод о победителе не сделан. Проверка относится к сохраненному HTML на 15 попыток и доступным исходным результатам R01-R16; полный итоговый отчет требует отдельной сверки.

## Область

Прочитаны `analyze_skill_loading.py`, `build_report.py`, `verify_report.py`, `accept_reviews.py`, `PROTOCOL.md` и `posthoc-findings.json`. Выборочно сверены result.json, stdout и реальные HTTP request bodies. Проверены анонимный маппинг, восемь импортированных оценок ревью и сохраненные результаты дополнительной проверки Stream. Вызовы моделей, запуск испытаний, изменения runner/inputs/raw results не выполнялись.

## Подтвержденные свойства

- `analyze_skill_loading.py:29-50` отделяет имена из начального каталога от содержимого skill. У каждого из 30 навыков есть три различные выбранные строки, уникальные среди снимков. Для всех записанных подтверждений R01-R15 повторно найдены как минимум две различные строки тела в строковых значениях указанного реального HTTP-запроса. Ошибок соответствия не обнаружено. Простого упоминания имени файла для этой метрики недостаточно.
- `build_report.py:48-58` включает в успешные решения только valid_attempt с task_pass=true. Расход агрегируется по завершенным попыткам отдельно от их успеха. По 15 строкам, фактически встроенным в HTML, независимо пересчитаны input/output, число завершенных/валидных попыток, сумма времени и медиана всех четырех групп. Все значения совпали с summary.json.
- Для R02, R03, R06, R08, R09, R11 и R13 сохраненный normalized input/output совпал с последним итоговым usage в stdout. Промежуточные сообщения повторно не складывались.
- `accept_reviews.py:16-24` связывает анонимный пакет с run через отдельный маппинг, требует корректного формата исходного review и не позволяет молча заменить уже принятую оценку. Все восемь текущих записей manual-review.json соответствуют blind-map.json. Проход ревью при построении HTML дополнительно зависит от формата и отсутствия изменений защищенных файлов.
- Отчет явно обозначен промежуточным. Отсутствующая оценка не названа неудачным решением. Между собой сравниваются A/B одного клиента; разница effort, адаптации skills, отсутствие полного выравнивания счетчиков и отсутствие человеческой разметки раскрыты.
- Замороженные файлы повторно проверены по experiment.json: несоответствий хэшей нет. Это не заменяет итоговую проверку всех будущих результатов.

## Дополнительная проверка Java Stream

Находка раскрыта в самостоятельном блоке HTML "Что не покрыли исходные тесты" и в предупреждениях соответствующих попыток. Основной балл не изменен.

Маппинг подтвержден: P13 = R09, P17 = R12, P25 = R10, P28 = R11. В `author-output.txt` оболочка исключения воспроизведена 8 из 10 раз для P13 и P17; в `oracle-output.txt` - 4 из 10 для замороженного эталона. P25 и P28 сохранили исходный объект во всех десяти дополнительных повторах. Эти числа точно отражены в posthoc-findings.json и HTML.

Текст не скрывает неоднозначность контракта между исходным объектом worker и исключением терминальной операции, ограниченность исходного sequential-теста и проблему самого эталона. Частоты корректно названы свидетельством воспроизводимости, а не оценкой вероятности. Обход хвоста parallel-источника также упомянут, но новое требование к числу чтений задним числом не добавлено. Противоположное направление различий у клиентов раскрыто.

## Границы заключения

`verify_report.py` проверяет уникальность HTML id, ссылки, frozen-хэши, число записей, уникальность sessions/workspaces и отсутствие assistant-history в начальном запросе. Он не пересчитывает все групповые метрики из raw results; их совпадение в этом обзоре установлено отдельным пересчетом. При финальной сверке нужно повторить именно пересчет, а не считать один зеленый verify_report достаточным доказательством всей арифметики.

Наличие двух строк тела подтверждает попадание фрагмента навыка в контекст. Оно не доказывает чтение всего файла, применение каждого правила или причинную пользу. Формулировка таблицы "попытки с телом навыка в контексте" и отдельные исходные якоря сохраняют эту границу.

Во время чтения R16 уже завершился, а HTML и skill-loading.json еще соответствовали срезу R01-R15. Это ожидаемый промежуточный срез, а не ошибочная арифметика. Перед финальным построением нужны свежие skill-loading.json/manual-review.json и сверка покрытия всех попыток. Изменения этих производных файлов после данного обзора автоматически не подтверждены.

Визуальный рендеринг браузером, все конечные решения и окончательные выводы этим обзором не проверены. Проверяющий сохранил только этот отчет.
