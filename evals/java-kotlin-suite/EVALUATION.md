# Проверка комплекта Java/Kotlin

Комплект содержит 30 навыков для написания и ревью кода. Каждый состоит из одного SKILL.md.
Этот каталог предназначен автору и оценщику, не является зависимостью навыков и не должен
автоматически загружаться при их использовании.

## Что проверено локально

- Frontmatter всех 30 навыков проверен skill-creator validator.
- Проверены формат одного файла, ссылки внутри репозитория, JSON корпусов и ASCII-пунктуация.
- В исходниках 36 каталогов навыков: 30 Java/Kotlin и 6 прежних workflow skills.
  Claude CLI с --plugin-dir также показал source inventory из 36 навыков.
  Сам inventory не доказывает загрузку/применение навыков моделью.
- Выполнено общее техническое и редакторское ревью инструкций, примеров и пересечений тем.
  Это самопроверка автора, не независимое модельное ревью.
- `python3 evals/java-kotlin-suite/check_local.py` выполнил 30 проверок выбранных библиотечных
  контрактов: 16 Java, 12 Kotlin и 2 ожидаемых отказа компиляции неправильных подстановок.

Окружение запуска: JDK 21, Kotlin compiler 2.3.21, kotlinx.coroutines 1.10.2. Использованы уже
доступные локальные зависимости; новых установок и загрузки зависимостей не было.
Скрипт требует эти артефакты в Gradle cache и JDK 21; при отсутствии сообщает об ошибке.
Он создает временный каталог и удаляет результаты компиляции после завершения.

Проверки показывают, например, поверхностность copy, повтор вычисления StateFlow.update,
потерю атомарности read-modify-write с volatile, коллизии associateBy/toMap, семантику Optional,
сохранение причины при cleanup и границы Collections.copy. Добавлены проверки decimal из double,
точного divide, overflow, DST gap/overlap, валютных fraction digits, повторного collect cold Flow,
области catch и потери промежуточного значения при conflate. Эти fixture проверяют отдельные
контракты, а не способность модели применять навык в произвольном приложении.

Spring/MVC/security paths, PostgreSQL transactions/migrations и полный проект с зависимостями
не исполнялись. Их инструкции проверены по официальным источникам; интеграционный успех не заявлен.
На этапе создания комплекта модельного A/B не было. Затем по отдельному запросу выполнена
дополнительная серия Codex: 60 сценариев этого каталога в двух условиях, 120 реальных ответов.
[HTML-отчет и первичные данные](../java-kotlin-benchmark/report.html) отделены от локальных проверок.
Claude CLI не авторизован: Opus-проба завершилась до inference, сравнение на Opus не выполнено.

## Корпус для модельной проверки

- `cases.json`: 60 открытых сценариев, по одному проблемному и корректному для каждого навыка.
- `rubrics.json`: отдельные критерии оценщика; не передавать испытуемой модели.
- `routing.json`: 23 проверки выбора нужной темы и отказа от ненужной загрузки.
- Существующие корпуса naming (24), SOLID (18), contracts (18) сохранены. Их ORIGINS.md содержит
  происхождение примеров из открытых проектов. Эти документы также не входят в runtime-навык.
- Всего во всех четырех корпусах: 120 авторских сценариев и 35 routing-сценариев. Это подготовленные
  задания с rubrics, а не 155 выполненных модельных тестов.

В дополнительном модельном A/B использованы только 60 сценариев cases.json из этого каталога.
Еще 60 углубленных сценариев naming/SOLID/contracts и все 35 routing-сценариев не исполнялись.
120 ответов A/B означают два ответа на каждый из 60 сценариев, а не выполнение всех 120 разных задач.

Фрагменты учебные, могут опускать imports и определения соседних типов. Не объявляй все фрагменты
компилируемыми. Библиотечные контракты проверены по документации; отрицательные изменения придуманы
для оценки, а не найдены в библиотеках. Личные и корпоративные проекты не использованы.

1. Зафиксируй точную модель, effort, инструменты, общие инструкции и снимок навыков.
2. Сравни свежие контексты A без проверяемого навыка и B с единственным SKILL.md. Остальные
   условия должны совпадать, включая core/rules. Исключи скрытую загрузку навыка в A.
3. Передай только context, request, files одного случая; скрой skill/id, если проверяешь routing.
   Не открывай rubrics, этот документ, предыдущие ответы и полный evals-каталог.
4. Оцени корректность сценария, минимальность решения и сохранение разрешенных вариантов.
   Нельзя оценивать по числу замечаний, классов, исключений или совпадению с одним именем.
5. Для заданий на правку оцени настоящий diff и исполненные проверки. Для review проверь
   отсутствие неразрешенных изменений. Не подменяй реальный результат обещанием тестов.
6. Сохрани ложные находки, пропуски, вредные советы, полезные решения, время и расход контекста.
   Для неоднозначного эффекта повтори пару. Независимую выборку зафиксируй до настройки по ней.

Корпус открыт при разработке и не является закрытым тестом обобщения. Хороший ответ на него
не доказывает устойчивую пользу для новой модели. Рабочий критерий - меньше ошибок относительно A
без роста вредных советов и с сохранением корректных решений.

## Итог общего ревью

| Тема | Критическая проверка | Допустимое решение, которое сохранено |
|---|---|---|
| Naming | Имя не скрывает эффект, rename сохраняет API | Короткие T/K/V и осмысленный Manager |
| SOLID | Подстановка и реальные зависимости | sealed/when и интерфейс с одной реализацией |
| Contracts | Состояние после отказа, aliases и равенство | Пустой диапазон и неполный builder |
| Domain | Идентичность и смысл ключей/значений | Простая map-группировка и CRUD script |
| Concurrency | Атомарность, scope, нагрузка и отмена | AtomicInteger без лишнего mutex |
| Errors | Нет ложного успеха и потери отмены | Nullable для нормального отсутствия |
| REST | Семантика статуса, границы и доступ | Разные ответы идемпотентного DELETE |
| Persistence | Общий constraint и действующий transaction | Insert с unique constraint без exists |
| Migrations | История, rollout, locks и восстановление | Простой переход при доказанном downtime |
| Collections | Коллизии, порядок, эффекты и lifetime | Простой stream и естественная map |
| Generics | Реальная связь типов и erasure | Producer covariance без оберток |
| Nullability | Отсутствие не подменяет бизнес-значение | orEmpty при явно разрешенном default |
| Testing | Проверяется реальная нужная граница | Unit test без Spring для чистой функции |
| Resources | Владелец и потребление до close | Stream коллекции без выдуманного I/O |
| Security | Object/tenant access и реальный механизм | Bind parameters с проверенным tenant |
| Refactoring | Сохранение порядка эффектов | Guard clause без новых классов |
| Interop | Старый Java binary client и JVM-сигнатура | JvmName для реального erasure clash |
| Serialization | Missing/null/default и wire-name | SerialName без глобальной смены mapper |
| Validation | Size/null, targets и активный Validator | Nullable raw DTO с нужными constraints |
| Time | Calendar day против duration, DST | nanoTime для локального elapsed time |
| Numbers | Decimal, rounding, overflow, equality | compareTo для числового сравнения |
| Resilience | Повтор после неизвестного эффекта, лимит in-flight | Нет retry небезопасного POST |
| Messaging | Crash между DB effect и ack | Inbox в одной DB-транзакции |
| Caching | Tenant в ключе, гонки заполнения | Локальный Caffeine без обязательного Redis |
| Observability | Cardinality и lifetime context | Ограниченный scope OpenTelemetry |
| Configuration | Effective value, unit, binding | Duration с явной единицей |
| Performance | DCE/constant folding и реальное измерение | Последовательный Stream без выдуманного дефекта |
| Reactive | Eager I/O, empty/zip, retry и conflate | Потеря промежуточного состояния, разрешенная контрактом |
| Modularity | Принятый API/internal boundary | Простой модульный монолит |
| Build | Реальные JVM targets и доверие к artifact | Согласованные toolchain и release |

Исправлено при ревью: потерянные локальные ссылки после перехода к одному файлу, неполная форма
декларации примера, область закрытия SQL-ресурса и неконкретная очередность KISS/SOLID/DRY в core.md.
Уточнена важная граница CLI: plugin details может показывать marketplace source; установленный
кэш проверяется отдельно. Он не обновляется от самого редактирования репозитория.

Повторы между навыками сохранены только там, где ошибка опасна в обоих контекстах: отмена,
remote effects, shallow copy, transaction/authorization activation. Ни один навык не требует
загрузки другого. Contracts устанавливает обещание, domain-modeling выбирает представление,
SOLID оценивает обязанности/зависимости; SQL-migrations разбирает изменение schema, persistence -
исполнение запросов. Такой выбор темы не требует загружать весь комплект.

## Проверка источников и ограничение вывода

В каждом из 30 SKILL.md проверяемые тезисы связаны с конкретными ссылками: метки S1 и далее
или прямой pinned source у примера. Факты языка/API, рекомендации именованных авторов и методика
этого комплекта разделены. Примеры адаптированы для объяснения; они не выдаются за баги open source.
Документация разных версий не означает требование обновить проект: навык требует сверить его версию.

В авторском проходе проверены определения, ограничения и существенные исключения, а не только HTTP
статус страниц. Удалена из оснований страница JFR, перенаправлявшаяся в общий каталог Oracle;
для AWS retries выбран доступный официальный Well-Architected документ. Общий источник о Kotlin
не используется как доказательство требований к Spring, HTTP или Android runtime.

Статическая проверка разрешения Markdown-ссылок не доказывает логического следования каждого
совета из документации. Сценарии выше, чтение источников и executable fixtures дают разные виды
доказательств; универсальная гарантия безошибочности и независимый review не заявляются.
Никаких выводов о специальном поведении модели Opus или улучшении ее качества пока не сделано.

[План отбора](../../SKILL_SELECTION.md) предлагает 20 базовых и 10 ситуационных навыков, варианты
слияния и явные контекстные развилки. Рекомендации о числе навыков и слиянии принадлежат автору
комплекта; технические источники не представляются доказательством оптимального числа файлов.

## Локальное подключение

Все 30 навыков скопированы в личный каталог ~/.claude/skills; байтовое равенство с исходниками
проверено. Перед обновлением прежних 15 копий проверены hashes предыдущей управляемой установки;
копии сохранены для восстановления. Чужие навыки и кэш установленного jkh не перезаписывались.
Для проверки загрузки используй новую сессию и прямой вызов /java-kotlin-<topic>. Само копирование
не считается прогоном модели. Commit, push и публикация не выполнялись.
