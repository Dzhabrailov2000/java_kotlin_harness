# Сборка и зависимости

Сохрани воспроизводимый набор зависимостей и целевой runtime. В ревью предложи правки;
выполняй их по задаче. Не обновляй весь stack из-за одной локальной зависимости.

## Установи среду

Прочитай wrapper, JDK сборки/запуска, Kotlin plugin, BOM/platform, repositories и lock/verification
files. Используй существующий build tool; Gradle-примеры ниже не являются поводом мигрировать Maven.
Точный порядок проверки - методика навыка.

## Проверь гарантии

- **Контракт Gradle:** toolchain выбирает инструменты JDK; sourceCompatibility/targetCompatibility
  не обеспечивают проверку доступности всех API целевого JDK. Для строгой Java cross-compilation
  используй подходящий `--release` совместно с выбранной toolchain. [S1]
- **Контракт Kotlin Gradle:** jvmTarget Kotlin и Java targetCompatibility проверяются на
  совместимость. Исправь источник различия, не выключай validation для сокрытия проблемы. [S2]
- **Контракт Gradle:** dynamic versions могут резолвиться по-разному во времени; dependency
  locking сохраняет выбранные версии. Lockfile не делает изменяемый artifact неизменяемым. [S3]
- **Контракт Gradle:** verification сравнивает checksums/signatures с доверенными данными.
  Автогенерация metadata не доказывает доверие к уже скачанному artifact; проверь происхождение. [S4]
- **Выбор навыка:** после upgrade проверь resolved dependency graph, нужную транзитивную версию,
  конфликты и фактический runtime. Имя версии в build-файле не считай единственным доказательством.
- **Выбор навыка:** используй принятый BOM/platform и точечные overrides с причиной. Не пинь
  каждую транзитивную библиотеку поверх согласованного набора без конкретной проблемы.
- **Выбор навыка:** не добавляй библиотеку для тривиальной операции, уже выражаемой stdlib.
  При необходимости зависимости оцени API, обслуживание, совместимость и выбранную лицензию.
- **Выбор навыка:** не обходи checksum mismatch удалением проверки. Установи изменение artifact,
  repository и происхождение новой суммы; не принимай изменившийся файл автоматически. [S4]

## Пример Gradle Java API

Адаптация toolchain и release для проекта с согласованным Java target 17. [S1]

~~~kotlin
java {
    toolchain.languageVersion.set(JavaLanguageVersion.of(17))
}
tasks.withType<JavaCompile>().configureEach {
    options.release.set(17)
}
~~~

17 - пример, не предписание обновить или понизить проект. Для смешанной сборки согласуй Kotlin
jvmTarget по версии plugin. Проверь наличие toolchain и настройки provisioning до запуска. [S1] [S2]

## Проверь

Проверь затронутые compile/test/package задачи и нужный runtime. Для публичной библиотеки проверь
потребителей и совместимость отдельно. Назови реально resolved версии и выполненные команды.
Не обещай полной воспроизводимости всех build outputs по одному lockfile: он фиксирует свой
аспект resolution; остальные входы сборки установи отдельно. [S3]
