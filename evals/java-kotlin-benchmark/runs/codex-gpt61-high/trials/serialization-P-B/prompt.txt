# Сериализация и внешний формат

Сохрани смысл данных при чтении и записи. Используй mapper и настройки проекта.
В ревью предложи правки, выполняй их по заданию. Проверки ниже - методика навыка.

## Установи wire-контракт

Прочитай реальные serializer, модули, настройки, payload и потребителей. Установи формат ID,
дат, чисел, enum и полей. Для каждого изменения реши, кто должен читать старый и новый payload.
Не принимай успешный round trip одной версией за достаточную проверку разных потребителей.

## Сохрани семантику

- **Контракт API:** `@SerialName` задает сериализованное имя kotlinx.serialization;
  Jackson `@JsonProperty` задает внешнее имя свойства. Сохрани wire-name при локальном rename,
  если внешний контракт должен остаться прежним. [S1] [S2]
- **Контракт kotlinx.serialization:** `ignoreUnknownKeys` по умолчанию false; включение
  разрешает пропустить неизвестные поля. Выбор строгости сделай по границе и совместимости. [S3]
- **Контракт kotlinx.serialization:** при `explicitNulls = false` null может не записываться,
  а отсутствие nullable-поля без default читается как null. Nullable-поле с non-null default
  может дать несимметричный encode/decode; не угадывай смысл пропущенного поля. [S4]
- **Выбор навыка:** если нужны "не передано", "очистить" и "заменить", вырази три состояния
  подходящим DTO/patch-протоколом и проверь mapper. Одной красивой Kotlin-сигнатуры недостаточно.
- **Контракт Jackson:** `@JsonIgnore` и `@JsonProperty` взаимодействуют, включая accessors.
  Проверяй реальный output, а не наличие аннотации на одном поле. [S2]
- **Рекомендация OWASP:** ограничь принимаемые поля через явный DTO/allowlist; не давай входу
  автоматически изменять защищенные поля entity. Выход также проверяй на лишние данные. [S5]
- **Выбор навыка:** для неизвестного enum/discriminator установи явный отказ или допустимый
  unknown-вариант. Не включай глобальное принуждение неверных значений к default ради зеленого теста.
- **Выбор навыка:** не меняй сериализацию общего ObjectMapper ради одного endpoint без проверки
  остальных его потребителей. Сохрани формат чисел, единицы и точность согласно заданному API.

## Пример официального API

Адаптация документации `SerialName`: внутреннее имя можно отделить от wire-name. [S1]

~~~kotlin
@kotlinx.serialization.Serializable
data class Project(
    @kotlinx.serialization.SerialName("name")
    val displayName: String
)
~~~

JSON-поле остается `name`. Это пример mapping; допустимость самого переименования для
Kotlin-клиентов оценивается отдельно. [S1]

## Проверь

Проверь чтение и запись отдельно: прежний payload, новый payload, missing, null, неверный тип,
неизвестное поле/enum и лишние защищенные поля по задаче. Используй настоящий mapper с модулями.
Не сравнивай порядок JSON-полей, если он не часть конкретного протокола. В находке покажи payload,
ожидаемый смысл, фактическое отличие и минимальную настройку или изменение DTO.
