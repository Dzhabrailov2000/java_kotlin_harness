# Числа, деньги и единицы

Установи точность и предметный смысл до выбора типа. В ревью предложи правки;
выполняй их по заданию. Политику денег и округления не выводи из технической библиотеки.

## Определи контракт

Запиши величину, единицу/валюту, допустимый диапазон, способ округления и границу применения.
Раздели хранение, промежуточный расчет и отображение. Выбор этих правил - решение задачи,
а не универсальное правило "деньги всегда с двумя знаками".

## Проверь арифметику

- **Контракт JDK:** `BigDecimal(double)` представляет переданное двоичное значение, поэтому
  `new BigDecimal(0.1)` отличается от точного десятичного `new BigDecimal("0.1")`. Получай точный
  decimal из подходящего исходного представления, а не исправляй уже потерянную точность. [S1]
- **Контракт JDK:** точное divide без rounding-контракта может бросить ArithmeticException
  для бесконечного десятичного разложения. Укажи согласованные scale/MathContext/RoundingMode. [S1]
- **Контракт JDK:** BigDecimal.equals учитывает scale, compareTo сравнивает числовое значение.
  Реши, какое равенство нужно, и согласуй hashCode ключа; не меняй его только в одном месте. [S1]
- **Контракт Kotlin:** целочисленная арифметика может переполниться; преобразование в меньший
  тип может потерять значение. Если переполнение недопустимо, выбери явную проверку. [S2]
- **Контракт JDK:** Math.addExact/multiplyExact сообщают о переполнении исключением.
  Применяй их к нужной гарантии, не меняя прежний контракт отказа молча. [S3]
- **Контракт JDK:** Currency.getDefaultFractionDigits различается у валют и может вернуть -1
  для псевдовалют. Это справочное значение, а не определение бизнес-правила расчета. [S4]
- **Выбор навыка:** не складывай разные валюты/единицы без явного преобразования. Используй
  именованный тип или существующий API, если примитивы допускают реальные перепутанные вызовы.
- **Выбор навыка:** допустимость NaN/infinity и отрицательного нуля задай явно для floating-point
  границы. Kotlin сравнения Float/Double и значений, типизированных иначе, имеют разные правила. [S2]

## Пример JDK

Адаптация документированного различия равенства. [S1]

~~~java
BigDecimal first = new BigDecimal("2.0");
BigDecimal second = new BigDecimal("2.00");
boolean sameRepresentation = first.equals(second); // false
boolean sameNumber = first.compareTo(second) == 0;  // true
~~~

Не заменяй equals на compareTo в value object без решения о scale и согласованном hashCode.
Это выбор предметного контракта; JDK описывает оба поведения, не выбирая одно для всех денег. [S1]

## Проверь

Проверь точную границу, округление, переполнение, сравнение и round trip через JSON/БД, если он
затронут. Expected возьми из требования или независимого расчета. В находке покажи числа,
неверный результат и минимальное исправление; не назначай HALF_UP или HALF_EVEN по привычке.
