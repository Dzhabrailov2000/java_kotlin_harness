# Claude series protocol addendum

Recorded before the first benchmark response of this series. The successful authentication probe was a separate trivial request, not a suite case.

- Series: claude-opus55-isolated-max. Explicit model ID claude-opus-5-5, effort max, two concurrent processes. Alias opus resolved to this canonical model in the probe.
- Keep the original frozen tasks, rubrics, skill texts, base prompt and shuffled order unchanged. A and B differ only by one full skill. No repetitions or automatic runner retries. Existing per-process transport timeout remains 180 seconds; failures are preserved.
- Each response and each grading request uses a new process and temporary working directory, safe-mode, empty tools, disabled skills, strict empty MCP configuration and no session persistence. Managed policy is not bypassed. Capture stream-json initialization, messages, final result, stderr, modelUsage and session ID. Reject observed tools, loaded customizations or missing initialization.
- Claude uses the original plain JSON instruction; Codex also enforced an output schema through its CLI. Record malformed JSON as failure, do not silently repair the response. This difference and different model/effort/system prompts mean cross-engine scores are descriptive, not a controlled model ranking.
- Grade each pair in a fresh Claude session with the same model and effort. Give only case, unchanged rubric and randomized X/Y answers, without A/B key or skill. Same-model grading is not independent expert evaluation.
- Audit ten cases selected in audit-plan.json before responses, plus every discordant pair and every pair with a failing grade. Do not change the rubric or skills after seeing answers. Record any grade correction separately.
- Normalize Claude input as input_tokens + cache_read_input_tokens + cache_creation_input_tokens. Preserve raw usage; cached input is cache_read_input_tokens. Thinking tokens are a subset of output. CLI list-price cost estimates are not actual subscription charges; actual monetary cost remains unknown.
- Main metric: full rubric pass, as in the original protocol. Also report primary issue/ok verdict agreement (diagnostic established during prior Codex analysis), false positives, harmful advice, tokens, process time and paired outcomes. This is one pass on a non-held-out author corpus, not deployment evidence or an automatic skill selection test.
- Preserve Codex outputs and original runner snapshot. Render both series with explicit model labels, limitations and separate accounting.

Isolation preflight: two responses in claude-opus55-max were rejected because initialization still listed installed and built-in plugins. Their raw logs and initial runner snapshot are preserved; they are excluded, not overwritten. A separate trivial probe with --setting-sources empty and explicit enabledPlugins=false returned empty tools, skills, MCP and plugins. These additional per-process flags define the main series. The two excluded responses were not graded or used to modify skills/tasks/rubrics. Both intended tasks will be run anew in the main series. Default built-in agent names remain in initialization but no Agent/tool is exposed or called.
