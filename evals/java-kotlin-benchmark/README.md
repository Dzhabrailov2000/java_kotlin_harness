# A/B-бенчмарк навыков

[Открыть HTML](report.html). Отчет автономный: CSS, JavaScript, замороженные тексты всех 30 навыков,
60 заданий, ответы и оценки встроены. Полные журналы CLI и запросы сохранены рядом. Публикации нет.

## Что измеряется

Содержательная корректность короткого ревью с одним явно переданным навыком против такого же
ревью без него. В каждой серии 60 сценариев x 2 условия = 120 ответов. Основной показатель -
прохождение всей рубрики. Дополнительный issue/ok показывает только совпадение главного вердикта.
Пропущенный пункт объяснения не равен пропущенному дефекту. Это не проверка автоматического
выбора навыков, установки плагина или создания работающего приложения.

Серии с реальными ответами:

| Серия | Модель и настройки | Основание идентификации |
|---|---|---|
| `codex-gpt61-high` | Codex CLI 0.157.1, `gpt-6.1-sol`, `high` | Клиентское имя; CLI предупредил о fallback model metadata, неизменяемая серверная версия неизвестна |
| `claude-opus55-schema-max` | Claude CLI 2.1.280, `claude-opus-5-5`, `max` | Model ID в initialization и modelUsage каждого ответа |

Сравнение A/B проводится внутри серии. Разные модели, настройки и оценщики не образуют
контролируемого рейтинга моделей. Одна попытка на условие; корпус открыт при разработке навыков.
См. [исходный протокол](PROTOCOL.md) и [дополнение для Claude](CLAUDE_PROTOCOL.md).

Каждый ответ и каждая оценка получены в новой сессии CLI и пустой временной рабочей папке.
В Claude проверены пустые списки plugins, skills и MCP; разрешен только встроенный форматировщик
StructuredOutput. Его вызовы учитываются отдельно от внешних инструментов. Оценщик получает
задание, неизменную рубрику и ответы с перемешанными метками X/Y, без ключа A/B и текста навыка.
Он использует ту же модель, что и испытуемая; авторский аудит также делает ИИ. Человеческой
независимой оценки нет. Стиль ответа может косвенно раскрывать группу.

## Данные и ограничения

- `frozen/manifest.json`: SHA-256 исходных 30 навыков, корпуса и рубрик; порядок 120 запусков.
- `runs/<series>/run.json` и `runner-snapshot.py`: параметры серии и точная версия runner.
- `runs/<series>/trials/<case>-A|B/`: запрос, схема, сырой stdout, stderr, ответ и расход токенов.
- `runs/<series>/judges/<case>/`: анонимизированный запрос, ответ и расход оценщика.
- `judge-label-key.json`: соответствие X/Y и A/B; не передается оценщику.
- `audit-plan.json`, `author-precheck.json`, `manual-audit.json`: план и результаты авторской проверки.
- `summary.json`: производные числа по обеим сериям; исходные ответы сохраняются отдельно.
- `ANALYSIS_NOTES.md`: разбор Codex; Claude - в каталоге своей серии.
- `probes/` и две исключенные Claude-серии: технические пробы, отдельно от основных результатов.
- [Проверка присланного аудита](AUDIT_RESPONSE.md): подтверждения, возражения и ссылки на доказательства.

В основном pass должны выполняться все must, ни одного must_not, ложного обязательного исправления
или вредного совета. Авторский проход охватывает десять заранее выбранных пар каждой серии и все
пары с провалом хотя бы одной группы. Поправки оценщика, если есть, записываются отдельно.

Claude input = input_tokens + cache_read_input_tokens + cache_creation_input_tokens. Чтение
и создание кэша показаны отдельно; thinking входит в output. Финальный result.usage учитывается
один раз. num_turns - счетчик CLI, не доказательство числа запросов к модели. Оценка CLI по
прайс-листу не равна платежу по подписке; фактическая денежная стоимость неизвестна.

Семь авторизованных проб Claude исключены: три короткие технические проверки и четыре ответа
при подборе изоляции/формата. Все задания заново выполнены в итоговой конфигурации; выборочных
повторов по качеству ответа не было. Прежняя ошибка авторизации сохранена отдельно с нулевым usage.

Во время оценивания исходники семи навыков были изменены в другой сессии. Замороженные тексты
и запросы сохранены. Результаты относятся к снимку `frozen`, а не к исправленным текущим файлам.
HTML перечисляет фактические расхождения исходников и установок на момент своей сборки.

## Повторить

Из корня репозитория; Python 3.9+ и авторизованный соответствующий CLI:

```sh
python3 evals/java-kotlin-benchmark/run_benchmark.py run \
  --engine claude --model claude-opus-5-5 --effort max --run claude-new \
  --workers 2 --limit 2
```

Проверь изоляцию и два `result.json`, затем повтори ту же команду без `--limit 2`.
Сохраненные ответы не пересоздаются. Затем:

```sh
python3 evals/java-kotlin-benchmark/run_benchmark.py judge \
  --engine claude --model claude-opus-5-5 --effort max --run claude-new --workers 2
```

До ответов новой серии зафиксируй `audit-plan.json`; после оценивания выполни авторский аудит.
Для Codex используй `--engine codex --model gpt-6.1-sol --effort high` и другое имя серии.
Алиас `opus` сам по себе не доказывает конкретную модель. При необходимости добавь
`--proxy http://127.0.0.1:43132`, только если этот локальный прокси уже работает. Системные
сетевые настройки и auth-файлы runner не меняет.

При timeout процесс и дочерние процессы завершаются; повторов внутри runner нет. Неуспешные
серии сохраняются. Фаза run отклоняет изменение параметров, базового запроса или runner под прежним
именем. Для judge указывай те же параметры; их совпадение дополнительно проверяет validator.
Seed задает порядок и метки, но не делает модель детерминированной.

Текущий итоговый HTML собирается так:

```sh
python3 evals/java-kotlin-benchmark/build_report.py \
  --run codex-gpt61-high --run claude-opus55-schema-max
```

## Проверка

```sh
python3 evals/java-kotlin-benchmark/validate_results.py \
  --run codex-gpt61-high --snapshot-only
python3 evals/java-kotlin-benchmark/validate_results.py \
  --run claude-opus55-schema-max --snapshot-only
```

`--snapshot-only` явно проверяет сохраненный эксперимент и сообщает о расхождениях текущих
файлов, не подтверждая их качество или синхронизацию. Проверка без этого флага дополнительно
требует совпадения исходников и двух личных установок со снимком; при известных расхождениях
она должна завершаться ошибкой.

Проверяются hashes, точные запросы, сырые ответы, модель, отдельные сессии/папки, отсутствие
внешних инструментов, учет usage, оценки, покрытие авторского аудита и совпадение HTML с данными.
`--partial --data-only` служит только для незавершенной серии. Это проверка сохранности и учета,
а не новая экспертная оценка всех Java/Kotlin-рекомендаций. Новые навыки требуют нового снимка
и отдельного эксперимента; существующий `frozen` не изменяется.
