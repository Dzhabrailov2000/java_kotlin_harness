# Каталог компонентов

Полный состав обвязки с назначением и местом установки. `install.sh` ставит
симлинки: skills в `~/.claude/skills/<имя>`, агентов, команды, хуки и
statusline пофайлово в соответствующие каталоги `~/.claude`, а общие методы
`self-correct`, `epic-decomposition`, `system-design-tradeoffs` дополнительно
в `~/.agents/skills/<имя>` для Codex. Описания ниже - краткие; полная
инструкция каждого компонента в его файле. Происхождение скопированных
компонентов - в [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

## Skills: предметные

| Имя | Назначение |
| --- | --- |
| api-design | Проектирование REST API: ресурсы, коды, пагинация, ошибки, версионирование |
| architecture-decision-records | Фиксация архитектурных решений как ADR с контекстом и альтернативами |
| database-migrations | Миграции схемы и данных, откаты, zero-downtime |
| hexagonal-architecture | Ports and Adapters, инверсия зависимостей, тестируемые use case |
| kotlin-comment-style | Стандарт комментариев в Kotlin: KDoc, "почему, а не что", ASCII |
| kotlin-coroutines-flows | Корутины и Flow: structured concurrency, StateFlow, тестирование |
| kotlin-patterns | Идиоматичный Kotlin: null safety, DSL, корутины |
| kotlin-testing | Тест-стек Kotlin-сервисов на Spring Boot: JUnit 5, MockK, Testcontainers, Kover; без Kotest |
| postgres-patterns | PostgreSQL: индексы, схема, RLS, оптимизация запросов |

## Skills: методы

| Имя | Назначение |
| --- | --- |
| epic-decomposition | Нарезка эпика на истории и подзадачи: три шкалы, подзадачи 3 или 5 SP, сумма равна оценке, порог резки; локальная конвенция, проект главнее |
| system-design-tradeoffs | Системные архитектурные решения с явным trade-off: ограничения, веер альтернатив с дисквалификаторами, цена, обратимость |

## Skills: дисциплина работы модели

| Имя | Назначение |
| --- | --- |
| scope-fence | Границы задачи: не больше и не меньше запрошенного |
| evidence-before-claim | Утверждения только с источником: проверено / выведено / предположено |
| adversarial-self-check | Одна честная попытка опровергнуть собственный результат перед сдачей |
| lead-with-outcome | Отчеты: вывод первым предложением, полные предложения, отбор фактов |
| context-hygiene | Экономия контекста: субагенты для широких поисков, чтение частями |
| self-correct | Цикл самокоррекции по критериям и источникам: Define, Attempt, Check, Decide, Stop, Report; вариант для кода с внешним исполнителем |

## Агенты

| Имя | Назначение | Права |
| --- | --- | --- |
| builder | Создание и точечная правка артефакта по задаче и подтвержденным замечаниям | пишет в переданный набор файлов |
| judge | Независимая проверка артефакта по критериям против источников: PASS / FAIL / UNVERIFIED | только чтение |
| code-architect | Архитектурный план фичи по паттернам существующего кода | чтение |
| code-explorer | Трассировка существующей функциональности и зависимостей | чтение |
| code-reviewer | Ревью изменений с доказательным гейтом для HIGH/CRITICAL; ноль находок - валидный итог | чтение, Bash для git |
| comment-analyzer | Точность и актуальность комментариев | чтение |
| database-reviewer | Ревью SQL, схем и планов по поставленным свидетельствам; недостающий план - UNVERIFIED | только чтение |
| pr-test-analyzer | Качество и полнота тестового покрытия изменений | чтение, Bash |
| silent-failure-hunter | Проглоченные ошибки, плохие fallback, потерянная пропагация | чтение, Bash |
| type-design-analyzer | Инкапсуляция и выражение инвариантов в типах | чтение |

Native `model` и `tools` агента задаются его frontmatter; менеджер проверяет
их при выборе. Независимый ревьюер конвейера - отдельный контекст Codex
(`gpt-6-astra`, effort `ultra`), а не эти агенты.

## Команды

| Имя | Назначение |
| --- | --- |
| harness | Печатает инвентарь установленной обвязки (запускает `hooks/harness-banner.js`) |
| adr | Завести ADR или сменить статус по конвенциям текущего проекта |
| epic | Разобрать эпик по `epic-decomposition` в формате планирования текущего проекта |
| meeting-notes | Протокол встречи из сырой расшифровки по конвенциям текущего проекта |
| meeting-prep | Prep-документ к встрече по материалам текущего проекта |

Четыре проектные команды находят проект, индекс, конвенции и шаблоны по
аргументам, рабочей директории и инструкциям проекта; в них нет заранее
заданных репозиториев.

## Хуки

| Файл | Когда запускается | Что делает |
| --- | --- | --- |
| harness-reminder.js | UserPromptSubmit (по `settings.reference.json`) | Подмешивает каталог обвязки с описаниями и просит применять только релевантное |
| harness-banner.js | Вручную, командой `/harness`; как hook не подключен | Печатает инвентарь: skills, агенты, команды, события хуков |
| ascii-punctuation.js | PostToolUse для Write и Edit | Проверяет записанный фрагмент на длинное или среднее тире; весь файл не проверяет |

Helper `run_claude_task.py` добавляет для вызова исполнителя собственный
PreToolUse hook (`harness_run_audit.py`), который отклоняет невыбранные
Skill, Agent и MCP; в пользовательские настройки он не ставится.

## Строка состояния

`statusline/statusline.js`: занятость контекста, лимит сессии на 5 часов и
недельный лимит из payload Claude Code (`context_window`, `rate_limits`);
своего учета не ведет. Включается ключом `statusLine` в `settings.json`.

## Скрипты

| Файл | Назначение |
| --- | --- |
| scripts/run_claude_task.py | Один вызов внешнего исполнителя: выбранные skills в system prompt, `selection.json`, гейт компонентов, doctor, сверка обвязки, `result.json`, журнал прогресса |
| scripts/claude_doctor.py | Запуск `claude doctor` после вызова; статус RECORDED / UNVERIFIED означает сбор диагностики, не исправность |
| scripts/harness_run_audit.py | PreToolUse-гейт по выбору менеджера и разбор `events.jsonl`: реальные вызовы против выбора |
| scripts/run_progress.py | Журнал прогресса `progress.jsonl` / `progress.log`, страница на 127.0.0.1, `emit` для этапов менеджера |
| scripts/run_progress.html | Страница монитора (отдается сервером, внешних ресурсов не грузит) |

Helper в PATH не устанавливается; вызывается по пути из корня обвязки.
