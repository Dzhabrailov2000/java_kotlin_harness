# Проверка изменений

Готово - это вывод команды, который ты видел, а не ожидание. Проверка идет от быстрой к полной, в отчет
попадают команды и их настоящий итог.

## Откуда брать команды
Сначала CLAUDE.md и README репозитория, потом файлы сборки: какие плагины подключены (ktlint, detekt,
Kover), есть ли свои задачи проверки, как запускается приложение. Команды из памяти и из других
проектов не бери.

## Порядок
1. Стиль: `./gradlew ktlintCheck`, если плагин подключен. Упал - `./gradlew ktlintFormat` и снова check.
2. Тест на изменение: `./gradlew test --tests "<полное.имя.Класса>"`. Метод с именем в обратных
   кавычках - в двойных кавычках целиком: `--tests "*TokenControllerTest.returns 404 when token is unknown"`.
   Для бага тест сначала должен упасть без исправления - иначе он не ловит то, что чинишь.
3. Интеграционные тесты: перед запуском `docker info`. Без Docker тесты на Testcontainers пропускаются
   или падают на старте, а сборка может остаться зеленой. Docker нет - так и пиши: "интеграционные тесты
   не запускались".
4. Полная сборка: `./gradlew build` - тесты, стиль, порог покрытия. Это последний шаг перед "готово".
   Maven: `./mvnw verify`, один тест - `./mvnw test -Dtest=Класс#метод`.
5. Сценарий: если изменение видно снаружи (HTTP-ручка, команда, миграция), прогони его сам, когда это
   возможно локально: подними приложение и сделай запрос, примени миграцию к пустой базе. Тесты
   доказывают то, что в них написано, сценарий - то, что просили.

## Что считается результатом
- "Проверено локально" - только то, что ты запускал. Что не запускалось, перечисли явно.
- Красное - первым в отчете, с выводом ошибки. Тест не правь, чтобы пройти: тесты и критерии не
  ослабляются.
- `SKIPPED` в выводе - повод разобраться, а не зеленый результат.
- Нестабильный тест повтори один раз. Повторилось - это находка, а не невезение.
