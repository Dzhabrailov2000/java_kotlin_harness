# ADR по правилам проекта

Аргументы: $ARGUMENTS

ADR фиксирует принятое решение, а не предлагает его. Правила оформления берутся из материалов проекта,
а не из памяти и не из примеров другого проекта. Где материалы молчат - спроси, не додумывай.

## 1. Решение должно быть принято
Если из запроса неясно, что именно решили, остановись и спроси. Статус `accepted` - только для решения,
которое пользователь принял; по умолчанию новая запись - `proposed` или аналог из шаблона проекта.
Непринятые технические детали не добавляй, все неутвержденное помечай явно.

## 2. Где живут ADR и их правила
По убыванию приоритета: аргументы и текущий каталог; CLAUDE.md или AGENTS.md репозитория и родительских
каталогов; индекс документации и индекс ADR; шаблон записи и две-три последние записи. Каталогов ADR
несколько - выбери по теме, при сомнении спроси. Каталога нет или он заброшен - скажи и спроси, где
писать. Одну запись в два места не клади.

## 3. Номер
Нет правила в материалах - максимум в индексе плюс один. Сверь индекс с файлами: файл без строки или
строка без файла - расхождение. Остановись и сообщи о нем, поверх расхождения не нумеруй.

## 4. Файл из шаблона
- Имя - по существующим записям: префикс, число цифр в номере, слаг. Правило выводи из всех имен, а не
  из одного файла.
- Тело - копия шаблона проекта: разделы, порядок, поля метаданных. Если живые записи стабильно
  отличаются от шаблона, покажи разницу и спроси; по умолчанию бери форму последних записей.
- Все плейсхолдеры шаблона заменены. Старые записи в прежнем формате не переписывай.

## 5. Содержание
- Контекст: какая проблема, какие ограничения и силы. Факты, а не выводы.
- Решение: что именно решено, в настоящем времени.
- Альтернативы: только реально рассмотренные, с причиной отказа. Для симметрии не выдумывай.
- Последствия: плюсы, цена, открытые вопросы.
- Одна запись - одно решение. Два независимых решения - предложи две записи.
- Сам выбор с компромиссами делается методом из скилла system-design-tradeoffs.

## 6. Индекс и кандидаты
Строка в индексе - в форме существующих: те же колонки, форма номера, ссылки и статуса. Нужной формы
статуса нет - спроси. Если в индексе есть раздел кандидатов и запись закрывает один из них, отметь это
в форме раздела; сам такой раздел не создавай.

## 7. Смена статуса и замена решения
ADR задним числом не правится: при смене статуса меняются только поле статуса и строка индекса. Замена:
старая запись получает `superseded by ADR-XXXX` в форме проекта, ее тело не трогается, новое решение -
отдельной записью. Ссылку на новую запись внутри старой ставь, только если так принято в проекте; при
сомнении спроси.

## 8. Перед сдачей
- Оформление по правилам проекта: язык, пунктуация, расшифровки аббревиатур, форма ссылок.
- Номер в имени файла, в заголовке и в индексе совпадает; формулировка в индексе не спорит с заголовком.
- Нет плейсхолдеров и решений, которых пользователь не принимал.
- Дата в метаданных и в индексе согласована; если проект понимает под ними разное, спроси.

В конце покажи путь к файлу, добавленную строку индекса, чего не хватило в материалах и что решено по
умолчанию.
