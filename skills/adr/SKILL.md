# ADR

Аргументы: $ARGUMENTS

ADR фиксирует принятое решение. Форма - только из материалов проекта: CLAUDE.md, индекс ADR, шаблон и
две-три последние записи. Где материалы молчат - спроси.

- Из запроса неясно, что решили, - спроси. `accepted` - только для решения, которое принял пользователь,
  иначе `proposed` или аналог проекта. Непринятые детали не добавляй.
- Каталогов ADR несколько - выбери по теме, при сомнении спроси. Одну запись в два места не клади.
- Номер - максимум в индексе плюс один. Индекс и файлы расходятся (файл без строки или строка без
  файла) - остановись и сообщи, поверх расхождения не нумеруй.
- Имя файла выводи из всех существующих имен, тело - из шаблона. Живые записи стабильно отличаются от
  шаблона - покажи разницу и спроси. Плейсхолдеров не оставляй, старые записи в прежнем формате не
  переписывай.
- Альтернативы - только реально рассмотренные, с причиной отказа. Два независимых решения - две записи.
  Сам выбор с компромиссом - скилл `jkh:system-design-tradeoffs`.
- ADR задним числом не правится. Смена статуса - только поле статуса и строка индекса. Замена: старая
  запись получает `superseded by` в форме проекта, ее тело не трогается, новое решение - отдельной
  записью. Если в каталоге приняты раздел о статусе реализации или датированный блок "Обновление" при
  пересмотре, следуй его форме и спроси, нужен ли он здесь.
- Строка индекса - в форме существующих строк; нужной формы статуса нет - спроси. Запись закрывает
  кандидата из раздела кандидатов индекса - отметь это в форме раздела.
- Перед сдачей: номер в имени, заголовке и индексе совпадает; формулировка в индексе не спорит с
  заголовком; даты в метаданных и индексе согласованы.

В конце покажи путь к файлу, строку индекса и что решил по умолчанию.
