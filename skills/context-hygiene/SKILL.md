# Гигиена контекста

Контекст - рабочая память, и она конечна. Каждый дамп файла, который не понадобился, вытесняет то, что понадобится. Деградация от замусоренного контекста незаметна изнутри: сессия просто начинает забывать ранние решения и повторять сделанное. Поэтому мусор надо не чистить, а не заносить.

## Когда применять

- Ответ требует сверки по многим файлам: "где у нас все места, которые...", аудит, сверка контракта с реализацией.
- Многочасовые сессии над эпиком, где важно не потерять ранние решения.
- Исследование незнакомой части кодовой базы или внешних источников.

## Когда НЕ применять

- Точечный вопрос, где известен файл и символ, - искать и читать самому, спавнить агента дороже, чем посмотреть.
- Короткая сессия с одним файлом - экономить нечего.

## Правила

1. **Широкий поиск - субагенту.** Если ответ требует прочитать много файлов, а нужен только вывод, - делегируй (Explore для поиска "где и что", code-explorer для трассировки фичи, general-purpose для многошаговых вопросов). В главный контекст возвращается заключение, а не прочитанные файлы.

2. **Сам читай только то, что будешь менять.** Файл, который правишь, - читать; файлы, по которым нужна только справка, - спрашивать у агента.

3. **Читай частями.** Если известно, где в файле нужное (номер строки из грепа, знакомая структура), - читать окно, а не 2000 строк. Большой файл целиком - это решение, а не рефлекс.

4. **Независимое - параллельно, одним блоком.** Несколько поисков, несколько чтений, несколько агентов без взаимных зависимостей запускаются одним сообщением. Последовательный запуск независимого - потерянное время; кроме того, каждый лишний раунд - лишний прирост контекста.

5. **Делегировал - не дублируй.** Запустил агента искать - не ищи то же сам параллельно; получил результат - не перепроверяй его повторным полным обходом (выборочная проверка одного факта - можно, см. `evidence-before-claim`).

6. **Не перечитывай установленное.** Факт, уже добытый в этом разговоре, не переустанавливается заново. Исключение - файл могли изменить с тех пор (другая сессия, скрипт, время).

7. **Вывод агента - тебе, а не пользователю.** Финальный текст субагента пользователь не видит. Важное из него пересказывается в твоем ответе по правилам `lead-with-outcome`.

8. **Долгоживущее - на диск, а не в контекст.** Промежуточные результаты многошаговой задачи (списки найденных мест, план миграции по файлам) пиши в scratchpad-файл: контекст может быть суммаризован, файл переживет это без потерь.

## Анти-паттерны

- **Пылесос.** Прочитать 15 файлов подряд "для понимания картины", когда нужен был ответ на один вопрос.
- **Агентофобия.** Ручной обход 30 файлов в главном контексте, потому что "быстрее самому".
- **Агентомания.** Субагент ради одного грепа с известным паттерном.
- **Последовательный поезд.** Пять независимых вызовов пятью отдельными раундами.
- **Недоверчивый дубль.** Полный повторный обход того, что только что сделал делегат.
- **Память в контексте.** Держать рабочий список из 40 пунктов в голове разговора вместо файла - и потерять его при суммаризации.

## Связь с обвязкой

- Инструменты правила 1: агенты `Explore`, `code-explorer`, `general-purpose`; для повторяющихся конвейеров - Workflow.
- Правило 8 - scratchpad сессии; результаты, нужные между сессиями, - в файлы проекта или memory.
- Пересказ результатов делегата - по `lead-with-outcome`; выборочная проверка фактов делегата - по `evidence-before-claim`.
