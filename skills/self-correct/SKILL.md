# Цикл самокоррекции (builder / judge)

Генерация и проверка разнесены по контекстам и по правам: агент `builder` умеет
писать, агент `judge` - только читать (Read, Grep, Glob). Ты, основная сессия, -
менеджер: формулируешь критерии, гоняешь цикл, принимаешь решения. Смысл цикла
не в том, чтобы Claude "подумал еще раз", а в том, что вердикт выносится в чистом
контексте и против внешних источников, а не по согласию модели с собой. Оба
агента - model: inherit, как в первоисточнике: оценщик слабее генератора
пропускает то, что генератор написал слишком гладко; для экономии judge можно
локально опустить до sonnet.

## Когда применять

- Артефакт с проверяемыми критериями и источниками: доки phase-0, отчеты,
  сверки, конспекты по расшифровке, исследования.
- Правка, после которой документ пойдет людям, и цена ошибки в фактах заметна.

## Когда НЕ применять

- Тривиальная правка - цикл дороже пользы.
- Код через текстового judge: он читает, но не запускает, и судьей для кода
  не является - для кода цикл собирается иначе, см. "Вариант для кода".
- Критерии не формулируются ("сделай получше") - сначала добыть критерии у
  пользователя, без них judge выродится во вкусовщину.

## Метод

1. **Define.** До первого вызова builder зафиксируй письменно: путь артефакта;
   критерии приемки (каждый - проверяемый); пути к источникам ground truth
   (исходные материалы, ADR, CLAUDE.md с конвенциями, реестр известных
   расхождений, если в проекте есть); запретную зону (источники - всегда
   read-only); лимит итераций (по умолчанию 3). Пометь, какие критерии ключевые:
   по умолчанию - факты и обязательные требования, стиль - нет. Машинно-измеримые
   критерии (длина, наличие файлов, тесты) проверяй сам командами - judge
   получает только смысловые.

2. **Build.** Субагент `builder`: задача, критерии, источники, запретная зона.
   В повторных заходах вместо задачи и критериев передавай список Issues
   последней итерации целиком и дословно, а путь, источники и запретную зону -
   заново: у builder каждый раз чистый контекст.

3. **Judge.** Субагент `judge`: путь к артефакту, критерии, источники, реестр
   расхождений. Judge артефакт не редактирует - только вердикт с file:line.

4. **Decide.**
   - Critical > 0 или Major > 0 - RETRY: повторный Build по правилам шага 2
     (Issues целиком плюс путь, источники, запретная зона).
   - Ключевой критерий UNVERIFIED - сначала добыть основание (найти источник
     самому или спросить пользователя), потом решать. Добыть недостающее
     основание - тоже ход цикла, не только правка текста.
   - Critical = 0, Major = 0, ключевых UNVERIFIED нет - COMPLETE. Minor - либо
     одним заходом builder, либо перечислить в отчете, на твое усмотрение.
   - ESCALATE - прекратить итерации и выдать Report с вопросами человеку.
     Ответ judge без Summary или в нечитаемом формате - тоже ESCALATE, не RETRY.

5. **Stop rules** - жесткие, проверять перед каждым RETRY:
   - максимум 3 итерации build-judge;
   - одна и та же Critical-проблема в двух итерациях подряд - стоп немедленно
     (сопоставляй по критерию и месту, не по формулировке; сомневаешься -
     считай, что та же): причина глубже правок - нет источника, критерии
     противоречат друг другу, задача недоопределена, не хватает прав или
     способностей модели;
   - PASS с первого захода - конец, не гонять цикл "для верности".

6. **Report.** И при COMPLETE, и при ESCALATE - финальный отчет: какая задача
   решалась; путь и состояние артефакта; по итерациям (1-я, 2-я, 3-я) - что
   менялось; остаток по Severity и Unverified; основания (файлы, источники,
   результаты проверок); конкретные развилки, где нужно решение человека.

## Внешний контур (по желанию)

Поверх цикла на длинной задаче можно поставить /goal (Claude Code >= 2.1.232;
это обертка над session-scoped prompt Stop hook): условие - "Critical = 0 и
Major = 0 по отчету judge для <путь>, ключевых UNVERIFIED нет, беспроблемные
места не переписаны, источники не изменены, не более 3 итераций, при
недостижении - отчет с остатками". Оценщик /goal файлы не читает,
он видит только ход сессии, поэтому /goal не заменяет judge - он лишь снаружи
следит, что сессия не объявила победу раньше времени. Постоянный prompt Stop
hook в settings.json сознательно не ставим: он срабатывал бы на каждый ход
каждой сессии проекта.

## Вариант для кода

Процедура та же - Define, Build, Decide, stop rules, Report, - но судейское
место занимают не текстовый judge, а исполняемые проверки:

1. Слой 1, обязательный: тесты, сборка, lint - менеджер гоняет сам командами
   после каждого Build. Красный прогон - это Issues для RETRY: builder получает
   вывод ошибок дословно и правит только причину падения.
2. Слой 2, смысловой: агент code-reviewer по диффу - у него Bash и дисциплина
   "репортить только уверенное". Его находки идут в тот же Decide.
3. Сверка с архитектурой и ADR - /arch-conformance, не judge.

Простая форма того же для одной задачи: /goal "тесты зеленые, lint 0, максимум
N ходов" - без субагентов.

## Калибровка judge

Перед первым боевым применением на новом типе артефактов прогони judge на двух
эталонах: заведомо чистом и заведомо испорченном (подложи фактическую ошибку
против источника, бездоказательное утверждение, нарушение конвенции). Judge
должен поймать все подложенное, не выдумать лишнего и развести Critical с
Minor. Ошибающийся judge ломает весь цикл, и чинить его потом дороже.

## Анти-паттерны

- Builder сам себе judge: генерация и оценка в одном контексте - главная
  ошибка, ради которой цикл вообще существует.
- "Найди N проблем" судье: ноль проблем - валидный итог, квота рождает шум.
- Полная перегенерация вместо точечной правки: ломает уже принятые места.
- Цикл без лимита итераций или без правила "та же Critical дважды - стоп".
- Вердикт модели как ground truth: основание - источники и конвенции,
  а не согласие Claude с собой.
- Давать judge права на запись "для удобства".
- Полная автоматизация с первого дня: высокорисковое (внешняя отправка,
  удаление, необратимые операции) - только через подтверждение человека,
  и результат первого прогона нового цикла смотрит человек.

## Связь с обвязкой

- `adversarial-self-check` - однопроходная самоатака, когда цикл не окупается;
  self-correct - когда есть внешние критерии, источники и артефакт стоит итераций.
- Judge реализует статусы `evidence-before-claim`: "подтверждено источником" -
  PASS/FAIL, "основания нет" - UNVERIFIED, никогда не молчаливый PASS.
- Механический слой уже стоит в хуках: ascii-punctuation.js проверяет пунктуацию
  на каждом Write/Edit - judge пунктуацией не занимается.
- `doc-sync` и `arch-conformance` - специализированные проверки своих доменов
  (согласованность представлений флоу, соответствие ADR); self-correct - общий
  случай "артефакт против критериев и источников".
