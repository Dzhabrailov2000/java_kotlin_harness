# Логи, метрики и трассировка

Сделай наблюдаемым нужный исход без утечки данных и бесконтрольного объема.
В ревью предложи правки; выполняй их по задаче. Набор сигналов выбери по диагностическому вопросу.

## Выбери полезный сигнал

- **Выбор навыка:** для операции определи начало/завершение, результат, длительность и допустимый
  контекст. Не добавляй лог каждого метода; назови вопрос, на который отвечает событие.
- **Рекомендация OWASP:** связывай события одной операции interaction identifier и записывай
  достаточный контекст безопасности. Не полагайся на разбор произвольного текста сообщения. [S1]
- **Рекомендация OWASP:** секреты (пароли, ключи, access tokens, идентификаторы сессий) в лог не
  записывай: убери или замаскируй. Прочие чувствительные данные - только при допустимом основании и
  защите. Очищай недоверенный ввод от log injection. [S1]
- **Контракт Micrometer:** комбинации tag values создают отдельные meters/time series.
  User/request/trace ID в metric tags дают неограниченную cardinality; выбери ограниченный набор. [S2]
- **Выбор навыка:** используй шаблон route вместо URI с ID, класс исхода вместо exception.message.
  Детальную корреляцию оставь подходящему контролируемому trace/log, сохраняя правила данных. [S1] [S2]
- **Контракт OpenTelemetry Java:** `makeCurrent()` возвращает Scope, закрытие восстанавливает
  прежний context. Ограничь scope блоком; не предполагай автоматический перенос через любую async-границу. [S3]
- **Выбор навыка:** различай число попыток и итоговых операций. Один успешный retry не должен
  скрывать нагрузку повторов; одна ошибка не обязана давать stack trace на каждом слое.
- **Выбор навыка:** не меняй значение метрики без проверки потребителей dashboards/alerts.
  Для фоновой работы проверь, где реально заканчивается операция и кто фиксирует failure/cancellation.

## Пример OpenTelemetry API

Адаптация официального управления scope. `span` и `operation` здесь уже созданные объекты. [S3]

~~~java
try (Scope ignored = span.makeCurrent()) {
    operation.run();
} finally {
    span.end();
}
~~~

Пример задает lifetime context/span, но сам по себе не записывает исключение и не назначает
статус span. Если это требуется, сделай это явно по API или проверь существующую instrumentation. [S3]

## Проверь

Проверь успешный исход, ошибку, отмену и async-переход по задаче. Убедись, что секреты отсутствуют,
число уникальных tags ограничено выбранным набором, scope закрыт, а завершение записано корректно.
Не выдавай наличие аннотации/зеленой сборки за получение сигнала backend-системой мониторинга.
В находке покажи потерянный сигнал, лишний объем или конкретную утечку и минимальную правку.
